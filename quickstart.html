Quickstart

Install Diffhold, add an agent of your own and connect it through agentgateway. The steps work on kind, K3s, RKE2 and hosted clusters (EKS, GKE, AKS); where a step differs by cluster, it says so. Commands are for bash or zsh. Keep one terminal open from start to finish, because later steps use files the earlier ones create.

The source and image are not public yet. They will be at the v0.1 release, and until then these steps need a checkout of the source. You build the image yourself and put it where your cluster can pull it.

1. Build the image and put it on the cluster

cd diffhold                    # your checkout of the source
make build                     # bin/diffhold, used below
docker build -t diffhold:dev .
DH=$(mktemp -d)                # private directory for keys and tokens, outside the checkout

Then get the image onto the cluster's nodes. Pick the row for your cluster:

ClusterDo this
kind
kind create cluster --name diffhold --image kindest/node:v1.35.0
kind load docker-image diffhold:dev --name diffhold
K3s, one node
docker save -o "$DH/diffhold.tar" diffhold:dev
# on the node (copy the file there first if Docker runs elsewhere):
sudo k3s ctr images import "$DH/diffhold.tar"
RKE2, one node
docker save -o "$DH/diffhold.tar" diffhold:dev
# on the node:
sudo /var/lib/rancher/rke2/bin/ctr --address /run/k3s/containerd/containerd.sock \
  -n k8s.io images import "$DH/diffhold.tar"
Several nodes, or a hosted cluster

Push to a registry the nodes can pull from (ECR, Artifact Registry, ACR, Harbor). Build for the nodes' architecture: Graviton and Ampere nodes are arm64.

docker buildx create --use     # once: the default builder can't push several platforms
docker buildx build --platform linux/amd64,linux/arm64 -t REGISTRY/diffhold:dev --push .

An image imported with ctr is not pinned, so the kubelet can remove it when it cleans up disk space. If a pod later fails with ErrImageNeverPull, import it again or use a registry.

2. Check what the cluster must allow

Most clusters need nothing here. These are the cases that do:

  • The API server must reach the webhook. The admission backstop is a webhook on port 9443 of Diffhold's pods.
    • GKE private cluster: add a firewall rule that allows the control plane's range to reach the nodes on TCP 9443.
    • EKS: with the AWS VPC CNI and the default cluster security group, nothing is needed. With a custom node security group, allow TCP 9443 from the control plane's security group. With an overlay CNI (Calico or Cilium in overlay mode), the control plane can't reach pod IPs, and the chart doesn't support that yet.
    • kind, K3s, RKE2 and AKS need no change.
    If the webhook can't be reached, writes by agent ServiceAccounts fail with failed calling webhook "backstop.diffhold.dev". Nothing else in the cluster is affected.
  • Pod Security. Diffhold's chart, the MCP server in step 6 and everything in examples/quickstart.yaml meet the restricted Pod Security Standard, so they also run where it is enforced cluster-wide, as on RKE2 with the CIS profile.
  • Certificates. By default the chart makes its own certificates, which are not rotated. On a cluster that matters, install cert-manager and add --set webhook.tls.mode=certManager --set grpc.tls.mode=certManager to the install in step 3.
  • Agent namespaces. The backstop only covers ServiceAccounts in the chart's agentNamespaces, agents by default. Put agent ServiceAccounts there.

3. Install Diffhold

examples/quickstart.yaml creates what the rest of this page uses: namespaces team-a, agents and oncall; the example agent's ServiceAccount agents/agent-sre-bot and a role for it in team-a; a Deployment team-a/web and a ConfigMap team-a/web-config for agents to work on; and an approver ServiceAccount oncall/alice. It is short and commented, so read it first.

kubectl apply -f examples/quickstart.yaml

Install the chart with the image settings for your cluster:

ClusterInstall
kind
helm install diffhold charts/diffhold -n diffhold-system --create-namespace --wait \
  --set image.repository=diffhold --set image.tag=dev --set image.pullPolicy=Never
K3s or RKE2, imported image
helm install diffhold charts/diffhold -n diffhold-system --create-namespace --wait \
  --set image.repository=docker.io/library/diffhold --set image.tag=dev --set image.pullPolicy=Never
Registry
helm install diffhold charts/diffhold -n diffhold-system --create-namespace --wait \
  --set image.repository=REGISTRY/diffhold --set image.tag=dev

If the nodes can't already pull from that registry, create a pull Secret in diffhold-system first, and add --set 'imagePullSecrets[0].name=SECRET' (quoted, for zsh).

The chart generates the webhook CA, the gRPC server and gateway client certificates, the admin token, the grant signing key and the audit signing key, and keeps all of them across upgrades.

4. Load a policy

kubectl apply -f examples/agentpolicy.yaml
kubectl -n diffhold-system get agentpolicies
NAME      AGENTS    MODE      READY   AGE
sre-bot   sre-bot   enforce   True    4s

Check the policy offline at any time, run its test suite, and check that the agent's ServiceAccount can't switch Diffhold off:

bin/diffhold policy check examples/agentpolicy.yaml
bin/diffhold test examples/agentpolicy_test.yaml          # 10/10 passed
bin/diffhold permissions check agents/agent-sre-bot       # OK    agents/agent-sre-bot

5. Add your own agent

An agent needs three things: a ServiceAccount in an agent namespace, RBAC for that ServiceAccount, and an AgentPolicy that binds the agent's name to it. The admission backstop refuses any write from that ServiceAccount that Diffhold did not grant, so the agent can't get around the policy with the ServiceAccount's own token.

kubectl apply -f - <<'EOF'
apiVersion: v1
kind: ServiceAccount
metadata: {name: agent-deploy-bot, namespace: agents}
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: {name: deploy-bot, namespace: team-a}
roleRef: {apiGroup: rbac.authorization.k8s.io, kind: ClusterRole, name: agent-workload-editor}
subjects: [{kind: ServiceAccount, name: agent-deploy-bot, namespace: agents}]
---
apiVersion: diffhold.dev/v1alpha1
kind: AgentPolicy
metadata: {name: deploy-bot, namespace: diffhold-system}
spec:
  subjects: [{agent: deploy-bot}]                       # the name the gateway sends
  credentials: {serviceAccount: agents/agent-deploy-bot}
  rules:
  - name: read-team-a
    verbs: [get, list, watch, logs]
    resources: [{kinds: ["*"], namespaces: [team-a]}]
    exclude: [{kinds: [Secret]}]
  - name: scale-team-a
    verbs: [scale]
    resources: [{kinds: [Deployment], namespaces: [team-a]}]
    conditions: ["object.spec.replicas <= 5"]
  - name: deletes-need-a-human
    verbs: [delete]
    resources: [{kinds: [ConfigMap, Pod], namespaces: [team-a]}]
    approval: {approvers: [group:system:serviceaccounts:oncall]}
EOF
kubectl -n diffhold-system get agentpolicy deploy-bot      # READY True
bin/diffhold permissions check agents/agent-deploy-bot

The ClusterRole agent-workload-editor comes from examples/quickstart.yaml. For a real agent, write a role with only what its job needs.

6. Run the MCP server and the gateway

kubernetes-mcp-server runs with no credentials of its own: no ServiceAccount token, and a kubeconfig with only the API server address and CA. It can do nothing without the per-call token Diffhold gives it.

kubectl apply -f test/e2e/stack/mcp-server.yaml
kubectl -n mcp rollout status deploy/kubernetes-mcp-server

agentgateway checks a JWT on every request and sends its subject to Diffhold as the agent's name. In production the JWT comes from your identity provider. To try it, make a test signing key and a token whose subject is deploy-bot:

go run ./test/e2e/stack keygen "$DH"                                  # jwt.key and jwks.json
go run ./test/e2e/stack sign "$DH" deploy-bot > "$DH/agent.jwt"     # valid for 1 hour

Download agentgateway 1.7.0 for your workstation from its release page: the asset for your OS and architecture. Save it as $DH/agentgateway and make it executable with chmod +x "$DH/agentgateway". The gateway runs on your machine and reaches the cluster through port-forwards, so this works the same on every cluster. Give it the client certificate Diffhold expects, and the config:

kubectl -n diffhold-system port-forward svc/diffhold 29000:9000 9001:9001 &
kubectl -n mcp port-forward svc/kubernetes-mcp-server 23001:8080 &
for k in ca.crt tls.crt tls.key; do
  kubectl -n diffhold-system get secret diffhold-gateway-client \
    -o jsonpath="{.data.${k//./\\.}}" | base64 -d > "$DH/gw-$k"
done

cat > "$DH/gateway.yaml" <<EOF
mcp:
  port: 23000
  policies:
    jwtAuth:
      mode: strict                      # reject requests without a valid JWT
      issuer: diffhold-e2e
      audiences: [diffhold-e2e]
      jwks: {file: $DH/jwks.json}
    mcpGuardrails:
      processors:
      - kind: remote
        host: 127.0.0.1:29000           # Diffhold, through the port-forward
        methods: {"tools/call": request}
        failureMode: failClosed
        metadata: {agent: jwt.sub}       # the agent's name, from the JWT
        policies:
          backendTLS: {cert: $DH/gw-tls.crt, key: $DH/gw-tls.key, root: $DH/gw-ca.crt, hostname: diffhold.diffhold-system.svc}
  targets:
  - name: k8s
    mcp: {host: http://127.0.0.1:23001/mcp}
EOF
"$DH/agentgateway" -f "$DH/gateway.yaml" &

For a shared setup, run the gateway in the cluster instead, mount Secret diffhold-gateway-client, and use diffhold.diffhold-system.svc:9000 as the host. See Connect agentgateway.

7. Connect the agent and try it

Any MCP client that can send a bearer token works. With Claude Code:

claude mcp add --transport http k8s http://127.0.0.1:23000/mcp \
  --header "Authorization: Bearer $(cat "$DH/agent.jwt")"

The token lasts an hour. After that every call gets 401 from the gateway: sign a new one as in step 6, then run claude mcp remove k8s and add it again.

Ask it to do things in team-a:

Ask the agent toWhat happens
List the pods in team-aAllowed.
Scale web in team-a to 3Allowed after a dry-run, with a token for exactly that change.
Scale web in team-a to 20Denied: object.spec.replicas <= 5 is false. The agent sees the reason.
Read the Secrets in team-aDenied: Secrets are excluded.
Delete the ConfigMap web-config in team-aHeld for approval. The agent sees the diff and the call ID.
Scale coredns in kube-system to 0Denied: no rule matches.

8. Approve a held call

kubectl -n diffhold-system get secret diffhold-gateway-client -o jsonpath='{.data.ca\.crt}' | base64 -d > "$DH/ca.crt"
kubectl -n diffhold-system get secret diffhold-admin -o jsonpath='{.data.token}' | base64 -d > "$DH/admin.token"
export DIFFHOLD_ADMIN=https://localhost:9001 DIFFHOLD_CA_FILE="$DH/ca.crt"
bin/diffhold approvals list --tls-server-name diffhold.diffhold-system.svc --token-file "$DH/admin.token"

list shows each held call with its diff and the exact command to approve it, with a --view that ties your approval to what you just read. Approve as alice, with her own token:

kubectl create token alice -n oncall --audience diffhold > "$DH/alice.token"
bin/diffhold approvals approve CALL_ID --view VIEW \
  --tls-server-name diffhold.diffhold-system.svc --token-file "$DH/alice.token"

Ask the agent to retry, and the delete goes through once. See Approvals. Every decision is in Diffhold's audit log:

kubectl -n diffhold-system logs -l app.kubernetes.io/name=diffhold --tail=-1 | grep '"decision"'

On kind, make e2e-stack drives this same path with a scripted client and checks every result.

Uninstall

Remove agent RBAC first. Without Diffhold's backstop, a token an agent's ServiceAccount gets some other way could use all of it, so helm uninstall refuses while any binding lets an agent ServiceAccount write. bin/diffhold uninstall --check-only --agent-namespaces agents lists those bindings (pass the chart's agentNamespaces, and --context if needed).

kubectl -n team-a delete rolebinding deploy-bot sre-bot-workload
kubectl -n diffhold-system delete agentpolicies --all
helm uninstall diffhold -n diffhold-system
kubectl delete namespace diffhold-system
kubectl delete -f test/e2e/stack/mcp-server.yaml
kubectl delete -f examples/quickstart.yaml --ignore-not-found
claude mcp remove k8s
kill %1 %2 %3                   # the port-forwards and the gateway
rm -rf "$DH"

A pre-delete hook stops Diffhold, revokes every outstanding per-call and read token, and removes approvals and Diffhold's other runtime state before the webhook goes away. If it refuses, kubectl -n diffhold-system logs job/diffhold-revoke-grants says why: delete the bindings it names and run helm uninstall again. Helm leaves a refused release as uninstalling; to keep Diffhold instead, roll back to the current revision, helm rollback diffhold REVISION -n diffhold-system with the last revision from helm history diffhold -n diffhold-system, and it can be upgraded again (see docs/upgrading.md in the repository). Helm leaves the AgentPolicy CRD in place; delete it with kubectl delete crd agentpolicies.diffhold.dev if nothing else uses it.

Where this has been tested. On 2026-11-10 the commands on this page were run in order on K3s v1.33.5 in Docker, with the restricted Pod Security Standard enforced on every namespace except kube-system, as on RKE2 with the CIS profile. Three things differed from the page: the image was imported with docker exec into the K3s container, agentgateway was already downloaded, and a scripted MCP client made the calls in step 7 instead of Claude Code. The script also waited for port-forwards and logged output, and counted the audit log instead of printing it. Every row of that table behaved as described, and after the uninstall only the CRD was left. On kind, make e2e-stack runs this path in CI on every push. Not tested yet: RKE2 itself, EKS, GKE and AKS (so the RKE2 import command and the notes in step 2 come from documentation, not a run), the registry and buildx path, imagePullSecrets, and a real LLM agent. Report anything that doesn't work.
