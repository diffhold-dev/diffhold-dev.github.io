The gap

Agents run kubectl now. Your controls still think in tool names and roles.

In April 2026 a coding agent with a broad token deleted a production database and its backups in nine seconds. Nothing asked what the change would do before it ran.

Tool names are too coarse

An MCP gateway can allow or deny resources_create_or_update. It can’t tell scaling to 3 from scaling to 300, or a new image from a privileged container.

RBAC grants windows

Kubernetes RBAC and access brokers grant a role for a period of time. Nothing approves the one change a person actually looked at.

Tokens outlive the decision

Whatever credential the agent holds works for everything its ServiceAccount allows, for as long as it lives, including after it leaks.

How it works

Five checks on every tool call, in this order

Diffhold plugs into agentgateway as an ExtMcp policy processor. In testing on kind, a write’s dry-run added about 11 ms (p50).

Map

The tool call becomes Kubernetes objects: kind, namespace, name, body. Tools that can’t be mapped, like raw shell, are denied.

Check

The agent’s AgentPolicy decides by verb, kind and namespace, plus CEL conditions on the object.

Preview

A server-side dry-run runs as the agent’s ServiceAccount and returns a field-level diff.

Hold

Risky rules wait for named approvers. An approval covers only the diff that was shown, and only once.

Grant

The call goes through with a per-call token. An admission webhook rejects anything the token tries beyond that change.

From the end-to-end suite that runs on kind in CI on every push.

Diffhold mints a short-lived ServiceAccount token for each allowed call and records a grant for it: the verb, the objects, the approved replica count or a hash of the exact object the dry-run predicted.

A validating admission webhook, scoped to agent ServiceAccounts only, compares every request against that grant. Humans and controllers never touch it, and if Diffhold is down, agent writes fail closed.

Grants are signed with a key agents can’t read, used once, and revoked when they expire.

AgentPolicy

One Kubernetes resource per agent

Policies live in the cluster and report their status like any other resource. The v1alpha1 schema is frozen: later releases only add optional fields.

apiVersion: diffhold.dev/v1alpha1
kind: AgentPolicy
metadata: {name: sre-bot, namespace: diffhold-system}
spec:
  subjects: [{agent: sre-bot}]       # JWT sub from the gateway
  credentials:
    serviceAccount: agents/agent-sre-bot
    grantTTL: 30s
  limits: {maxObjectsPerCall: 3, ratePerMinute: 120}
  rules:
  - name: operate-team-a
    verbs: [apply, scale]
    resources: [{kinds: [Deployment], namespaces: [team-a]}]
    conditions:
    - "object.spec.replicas <= 5"
  - name: destructive
    verbs: [delete, exec]
    resources: [{kinds: ["*"], namespaces: [team-a]}]
    approval: {approvers: [group:team-a-oncall], timeout: 15m}

Rules match verbs, kinds and namespaces in order. CEL conditions see the proposed object, so a limit can read replicas or every container image.

Approvals name users or groups as your API server knows them. Approvers sign in with their own Kubernetes or OIDC token; the agent can never approve itself.

Audit mode records what would have been denied without blocking, so you can roll a policy out safely.

Policy tests run in CI with diffhold test, which checks expected allow, deny and approval for each tool call.

Security

Threat-modelled before anyone runs it

The threat model lists 25 threats with status and evidence. The seven that blocked any outside use are fixed, and each fix started with a test that reproduced the attack.

IDENTITY
The agent identity comes only from the gateway’s authenticated metadata, such as the JWT subject. Headers are ignored.
TRANSPORT
The gateway connection requires mutual TLS. The Helm chart generates both certificates.
CONTENT
Apply tokens are bound to a hash of the exact object the dry-run predicted.
GRANTS
Grants are HMAC-signed with a key only Diffhold can read, and used once.
APPROVERS
Approvers authenticate as themselves; counts, groups and timeouts are enforced and recorded.
EVIDENCE
Hash-chained audit log with diffs and approvers, and signed checkpoints of its head. Secret values are always redacted.
SELF-CHECK
Diffhold checks every agent ServiceAccount for permissions that could switch it off, and can refuse to serve those agents.
LIMITS
Per-agent rate limits and a cap on open approval requests keep a runaway agent from flooding people.
